# 오픈소스 자동 포렌식 에이전트 시스템 연구 (팀 스초생)

한림대학교 소프트웨어캡스톤디자인 프로젝트 저장소입니다.  
디지털 포렌식 CTF 벤치마크(118문항)를 대상으로 AI 포렌식 에이전트(`Claude Opus 5.5`, `Qwen 3.8 Max`)의 자동 분석 성능과 한계를 정량·정성적으로 검증하고, 사람과 AI의 탐색 경로 차이 및 병목 지점을 분석했습니다.

- **라이브 대시보드**: [https://sbccsera.github.io/SBCC/](https://sbccsera.github.io/SBCC/)
- **지도교수**: 박성미 교수님
- **팀원**: 진세라(`@SBCCsera`), 박제윤(`@SBCCjeyoon`), 전시연(`@wjstldus616`)

## ① 문제 정의서

- **대상 및 문제**: 디지털 포렌식 조사에서 생성형 AI·에이전트를 활용해 증거를 자동 분석하고 사건을 재구성하려는 시도가 늘고 있으나, 실제 환경에서 에이전트가 어느 단계에서 왜 실패하는지 정량적으로 규명한 기준이 부족합니다.
- **초기 목표 및 방향 전환**:
  - **초기 구상 (프로젝트 시작 시)**: '생성형 AI 기반 타임라인 분석 및 사건 재구성'을 주제로 지도교수 자문을 받아, 선행연구와 스코프를 조정한 뒤 필요한 분석 모듈을 개발하고 Autopsy 플러그인으로 구상하는 것을 목표로 삼았습니다.
  - **목표 전환 (118문항 평가 및 오답 라벨링 후)**: 전체 118문항 기준선 평가와 오답 라벨링을 진행하면서, 현 단계에서는 성급하게 플러그인을 구현하기보다 AI 에이전트가 실제로 막히는 지점(추론 이전 단계 병목·도구 제약 등)을 깊이 분석하는 것이 우선이라고 판단했습니다. 이에 따라 후속 연구와 실무 개발에 기초 자료로 기여할 수 있도록 **심층 병목 분석 및 학술 논문 작성**으로 방향을 전환했습니다.
- **검증 기준**:
  - 전체 118문항 기준선 평가 **최소 3회** 반복 검증 시도
  - **2개 이상** 이종 모델 교차 검증 수행

## ③ 동작하는 배포물

누구나 브라우저에서 118문항 평가 결과, 오답 유형 분포, 힌트 복구율, 대표 사례 비교를 탐색할 수 있도록 정적 웹 대시보드와 Docker 실행 환경을 제공합니다.

- **웹 대시보드 (GitHub Pages)**: [https://sbccsera.github.io/SBCC/](https://sbccsera.github.io/SBCC/)
- **Docker 로컬 실행**: 저장소 루트의 `Dockerfile`, `index.html`, `data/`를 기반으로 로컬 환경에서 동일하게 재현할 수 있습니다.

```bash
git clone https://github.com/SBCCsera/SBCC.git
cd SBCC
docker build -t sbcc-dashboard .
docker run -d -p 8080:80 sbcc-dashboard
```

## ⑤ 한계 및 윤리·보안 검토

- **데이터셋 편향 및 환경 제약**: 본 연구는 공개 디지털 포렌식 CTF 문제(118문항)를 기반으로 했으므로, 실제 기업·수사 현장의 대규모 비정형 디스크·모바일 이미지와 난이도 및 환경 차이가 존재합니다. 또한 미복구 실패의 70.0%(49/70건)가 도구·환경 제약(로컬 폴더 미마운트, 탐색 깊이 제한 등)에서 발생해 모델 자체의 추론 한계와 환경적 요인이 혼재되어 있습니다.
- **개인정보 및 민감정보 처리**: 실험에는 모두 공개된 교육·경진대회용 가상 포렌식 이미지를 사용했으며, 실제 개인의 민감정보나 실무 사건 데이터는 포함하지 않았습니다. 저장소 내 문서에서도 학번·연락처 등 팀원 개인정보가 노출되지 않도록 제외했습니다.
- **오판 시 피해 가능성 및 대응**: 포렌식 에이전트가 증거를 놓치거나(`#65`, `#66` 조기 종료형) 존재하지 않는 경로·아티팩트를 단정(`#101` 과잉 탐색 후 추측)할 경우, 실제 조사에서는 무고한 판단이나 핵심 증거 누락으로 이어질 수 있습니다. 따라서 현 단계의 AI 에이전트는 최종 판단 주체가 아니라 **사람의 검증을 전제로 한 보조 탐색 도구**로만 활용해야 합니다.

## 저장소 구조

- `01_literature_review/` : 논문 선행연구 정리 자료
- `02_claude_baseline/` : `Claude Opus 5.5` 1·2차 기준선 평가 및 `T1-T4` 문항 분류
- `03_hint_recovery/` : 오답 라벨링 및 힌트 제공·구체화 재실험 데이터
- `04_deep_analysis/` : `Discovery/Reasoning`, `Extraction/Parsing` 재실험 및 대표 사례 비교
- `05_qwen_validation/` : `Qwen 3.8 Max` 36문항 교차 검증 결과
- `06_docs/` : 학술 논문 초안, 최종 보고서
- `index.html`, `Dockerfile`, `data/`, `docs/` : 웹 대시보드 및 컨테이너 배포 파일
